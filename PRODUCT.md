# Product

## Register

product

## Users

Developers who use agent CLIs or the ChatGPT desktop app throughout the day and
want passive writing practice without leaving their normal workflow. They are
usually focused on completing technical work, so feedback must be immediately
understandable, optional to explore, and quieter than the host conversation.

## Product Purpose

Redpen reviews every submitted prompt, shows a corrected version and a more
natural phrasing, and helps users build language intuition over time. It is a
coach, not a rewriter: the original prompt reaches the assistant unchanged,
feedback stays outside the model context, and the user remains in control of
whether to read, expand, copy, or dismiss the coaching.

## Brand Personality

Precise, encouraging, and unobtrusive. Redpen should feel like a thoughtful
editor making a small note beside the user's sentence, never like a grading
dashboard, alarm, or competing assistant.

## Anti-references

- Heavy third-party extension cards that visually detach from the host UI.
- Gamified scoreboards and red, yellow, or green alarm-like score pills.
- Generic AI styling such as glass panels, gradient text, glows, and decorative
  motion.
- Interruptive dialogs, forced tutorials, or feedback that competes with the
  user's primary task.

## Design Principles

1. Keep the conversation primary. Coaching should stay attached to the prompt
   it reviews without overtaking the thread.
2. Teach in layers. Show the useful correction first, then reveal deeper
   guidance only when requested.
3. Communicate meaning before metrics. Translation, correction, and unchanged
   states need plain-language labels before any numeric score.
4. Earn the red pen. Use one restrained editorial mark and semantic edit
   notation instead of broad decorative color.
5. Respect the host. Inherit typography, theme, density, and interaction
   conventions wherever practical while preserving robust fallbacks.

## Accessibility & Inclusion

Target WCAG 2.1 AA. Every action must work with keyboard and screen readers,
dynamic states must be announced without stealing focus, and edit meaning must
not rely on red and green alone. Respect reduced-motion preferences, support
200% zoom, long and multilingual text, mixed scripts, RTL content, and high
contrast environments.
